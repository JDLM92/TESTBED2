Summary

The previous manual scenario form is replaced with the InflectionPoints lens. A person selects a supported 360° place; the system exposes its current reading, shows the reference cases that inform a single possible direction, and leads into the paired immersive comparison. The person does not choose interventions, write prompts, or configure visual settings.

MVP boundary: this static version uses three verified places and their existing paired panoramas. It deliberately does not imply that a live locator, image generator, or evaluator is running. Those services have a clear insertion point in the flow.

Flow: Place lens

Entry point: “Analyze a place” from the landing page.

Steps

  1. 1Choose a supported place

    A fast search and visual result list make the three verified 360° places easy to browse. Each result is a button with an image, location, and scene type; selecting it reveals a confirmation card.

    Primary action: Understand this place → Read the scene

    No-match state: the experience explains that coverage is limited, keeps the search term visible, and offers “Browse places” rather than a dead end.
  2. 2Read the current scene

    Named progress steps show the intended agent work: checking the source, reading movement and public-realm conditions, matching comparable situations, and preparing a place-specific direction. The completed read is concise and inspectable.

    Primary action: See the direction → Ground the possible future

    Recovery: “Choose another place” returns to the search with the selection still available; no work is lost.
  3. 3Ground one direction

    A parallel Now / Possible 2040 brief makes the change legible. Reference cards explain transferable mobility moves from the other InflectionPoints places, rather than copying another city’s look.

    Primary action: Create the possible future → Prepare the comparison

    The system offers one evidence-led direction. It does not expose a menu of urban-design preferences.
  4. 4Prepare and check the visual

    A second visible run represents the future rendering pipeline: visual brief, candidate changes, place continuity, and mobility legibility. The finished card lists the visual checks that matter for the selected scene.

    Primary action: View the comparison → Enter the immersive scene

    MVP behaviour: the run hands off to the verified paired panorama already in the library. “Cancel run” preserves the grounded direction and returns to it.
  5. 5Compare Now and Possible future

    The immersive viewer opens in Now. Dedicated states, hold-to-compare, keyboard support, and the “What changes?” sheet help people perceive the spatial difference without overlaying the scene with dense controls.

    Primary action: Hold to compare → Reveal the opposite state

    The future is labelled as a possible, evidence-led direction—not a forecast or a certainty.

Next integration points

  • Replace supported-place search with a licensed location and 360° viewpoint service, including clear coverage and consent boundaries.
  • Connect the reference cards to a versioned mobility-evidence repository with source confidence and review ownership.
  • Add a server-side orchestration layer for scene analysis, rendering, and an independent visual evaluator; do not expose model keys in the static site.
  • Persist place, source view, evidence, run status, and evaluation results so a failed visual can be retried without losing the work.
  • Define release thresholds for camera continuity, local context, people, greenery, infrastructure ageing, and visible mobility change.
